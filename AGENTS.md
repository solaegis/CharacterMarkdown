## Learned User Preferences

- When asked to implement an attached `*_plan.md` build plan, do not edit the plan file; update the character profile export, alignment checklists, and related artifacts only. Do not recreate todos when the user says todos already exist; mark them in progress and complete them in order.
- Example build plans should use current in-game ESO names (e.g. Champion Point stars), not deprecated pre–Update 29 labels.
- User expects ESO mechanical correctness in example build documentation: skill bars must match equipped weapon type, each morph appears at most once, and bar tables include ultimates; document **slotted morph names as shown in the skills UI** (not unmorphed base or wiki-only labels—e.g. **Inspired Scholarship → Recuperative Treatise**, not **Tome-Bearer's Inspiration** after morphing); Champion Point constellations are capped at **4 stars per constellation**; Daedric summons use **slot 5 on both bars** (same ability) or are omitted entirely—never on one bar only.
- In build plans, use real ESO ability lines only (base → sibling morphs); do not invent skill names or tell the user to morph from an already-morphed skill to a nonexistent ability.
- When the user frames a build as class-identity-first (e.g. true necromancer first), keep native class skill lines by default; only subclass a line when the foreign line clearly outperforms the native one it replaces. When reviewing one character's plan for improvement, do not use other characters' builds as the baseline unless asked.
- ESO **companion gear is separate from player character gear** — only **Companion's** weapons/armor with companion-only traits (Quickened, Aggressive, Bolstered, etc.); never fictional **"Companion's {player set}"** names, player sets (Julianos, Clever Alchemist, Divines), or **5-piece set bonuses**; acquire via merchant whites and **Superior+** drops while the companion is active — **not** via player crafting handoff from **Gear and crafting**.
- Target gear in build plans must always be **craftable** (account crafter / crafting stations). Do not plan primary loadouts around overland farming, dungeon monster sets, trial drops, or other non-crafted acquisition unless the user explicitly asks for an exception.
- When changing addon settings (defaults in `src/settings/Defaults.lua`, LAM panel labels/checkboxes/presets in `src/settings/Panel.lua`, or `ToggleAllSections`), always update `docs/settings-presets-matrix.md` in the same change so factory defaults and every preset column stay accurate.
- Do not bulk-reformat existing `examples/solaegis/na/*_plan.md` files to the canonical structure unless the user explicitly asks; apply the exemplar outline to new and heavily revised plans only.
- When a LAM preset enables sections that lack generators or `Markdown.lua` registry wiring, implement or wire the missing output rather than disabling preset checkboxes or narrowing preset scope.
- For large addon review/fix passes, prioritize by severity (correctness and crash bugs first), validate with luacheck/StyLua/tests, and work in reviewable batches.
- When asked to confirm an example export's **default settings** output, audit H2 sections against **factory defaults** and likely LAM presets (do not assume Reset to Defaults); use `scripts/validate_example_preset.py` and `docs/settings-presets-matrix.md`.
- When drafting ESOUI posts, comments, or replies (addon page comments, forum threads, etc.), write the body in **BBCode** (`[B]`, `[I]`, `[LIST]`, `[*]`, `[URL]`, `[CODE]`, …), not Markdown — ESOUI uses BBCode for formatting.

## Learned Workspace Facts

- Character examples live under `examples/{account}/{location}/{slug}.md` (identity = account + location + slug; same slug allowed across different accounts or locations, not duplicated for the same account and location). Slugs are **lowercase with underscores** (not hyphens). `task examples:check` validates against live SavedVariables (`ZO_Ingame.lua` / `CharacterMarkdown.lua`); remove example profiles whose triple is missing from SV.
- Solaegis NA character examples and build plans live under `examples/solaegis/na/` (paired profile markdown + `{slug}_plan.md`). **Paired plans must be build guides** authored from `template_plan.md`, not CharacterMarkdown profile exports saved as `_plan.md`. Non-character docs live in `examples/fixtures/`.
- Solaegis-style build plans follow the canonical layout in `docs/plan_structure.md`; use `examples/templates/template_plan.md` as the copy-paste skeleton for new plans and alignment (`build_plan_template.md` is a legacy alias). Filled exemplars: `silent_snow_falls_plan.md`, `kellen_dysart_plan.md`. Reference `docs/subclassing.md` for Trinity / subclassing theory. CP recommendations use exact star names and caps from `examples/templates/champion_points_reference.md` (generated from `champion_points.yaml`). Paired `{slug}_plan.md` + character profile live under `examples/{account}/{location}/`.
- **Build plan H2 order (required for new and heavily revised plans):** (1) title + profile link + pitch, (2) **Build at a glance** (stats, mundus, sets, bars, companion, primary mount + doc-map links), (3) **Roleplay**, (4) **Trinity configuration** (mermaid + one unified table), (5) **Combat kit** (`### Skill bars`, `### Rotation`, `### Passive skills`), (6) **Gear and crafting** (`### Set rationale`, `### Target loadout`, `### Crafting handoff`), (7) **Champion Point Mapping**, (8) **Companion strategy**, (9) **Collectibles** (`### Mount`, `### Pet`, `### Dye and style`), (10) **Next steps / in-game checklist** with gear phases as labeled steps — no separate Gear Phases H2.
- **Build plan structural rules:** one execution checklist only (merge gear phases into it); no duplicate H2 emoji/titles; trinity = mermaid + one table (no third slot-only table); mount and visual identity under Collectibles, never between Gear and Champion Points; **Roleplay** includes **Suggested Custom Title** (≤100 chars) and **Build Notes** paste text (≤1,900 chars) for LAM Custom Title / Build Notes; **Companion strategy** uses **Loadout** + **Acquisition** rows per companion tier (never **Core Sets** with player set names); optional Tier B polish when creating plans — use Gear and Crafting subsections and passives immediately after skill bars within Combat kit.
- Crafting support specs for builds may be separate markdown files (e.g. `examples/fixtures/karakedi_crafting.md`) referenced from the main plan.
- `examples/solaegis/na/masisi.md` documents the account crafter used for gear-crafting plans tied to other Solaegis characters.
- CharacterMarkdown exports in `examples/` are source of truth for in-game state; they are not necessarily **factory defaults**—many match a LAM preset (e.g. `silent_snow_falls.md` = Solo PvE). Use `scripts/validate_example_preset.py` (`--profile factory-defaults` or `solo-pve`, or `auto`) when auditing section inclusion. When saving multi-chunk exports as examples, copy each chunk once in order—overlapping paste can duplicate sections or corrupt fenced-code boundaries (notably between Champion Points diagram and legend `mermaid` blocks). When syncing a plan from a profile, label **live** (equipped) vs **target** in Build at a glance and gear, and keep skill bars aligned with slotted actives and equipped weapons from the export.
- Paired character profiles should link to their `{slug}_plan.md` with a section anchor table; highlight the plan checklist as the primary in-game entry point.
- `docs/settings-presets-matrix.md` is the canonical matrix of factory defaults vs LAM presets (Minimal, Solo PvE, PvP Build, Achievement Hunter, Crafter) for every settings-menu checkbox; keep it in sync whenever settings code changes. LAM presets call `ToggleAllSections(false)` first; any checkbox not turned back on by the preset stays off until Reset to Defaults or manual toggle.
- Before removing or rewriting ESO API call sites, verify disputed function/event names against the bundled `ESOUIDocumentationP50.txt` (and in-game globals when needed). **Action bar slot constants** (`ACTION_BAR_ULTIMATE_SLOT_INDEX`, etc.) are **0-based**; `GetSlotBoundId` and related bar APIs use **1-based** indices (ultimate = slot 8).
- Markdown table of contents lists only sections whose generators produced non-empty body content (two-pass generation), not registry conditions alone.
